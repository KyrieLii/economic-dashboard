# 历史数据留存方案

## 已确认需求

用户在2026-11-27明确要求记录历史数据，以便查看数据变化。历史留存属于核心功能，不能仅缓存最新值。

## 当前实现（2026-11-27）

已实现SQLite/libSQL历史、价格/成交量/来源修订、采集状态、运行记录、租约，区间曲线、日期筛选、CSV、备份及空库恢复。
实际历史约2–5年，逐指标显示覆盖。观测值存SQLite REAL（双精度），不是任意精度十进制原文档案。
不保存全量原始响应和开高低价；固定周/月末变化、跨指标归一化、全历史定期自动复核仍为后续规划。

## 建议的观察功能

- 单指标历史曲线，支持1个月、3个月、1年、全部及自选时间区间。
- 展示日、周、月、年初至今的变化，历史不足时明确显示不可计算。
- 支持查看任一历史交易日的数值、来源及修订信息。
- 成交量/额可显示相对过去20个有效交易日均值；不足20个观测值时不冒充完整均值。
- 不同量纲的指标可在清晰标注的情况下比较累计涨跌；利率仍优先比较基点变化。
- 支持导出选定时间段的数据是候选功能，尚未实现。

## 数据结构原则

以下是逻辑设计，不预先限定数据库与实现技术。

| 实体 | 需要保存的内容 |
| --- | --- |
| 指标定义 | 稳定ID、名称、资产类别、来源代码、单位、币种、频率、时区、计量口径、合约与调整方法 |
| 历史观测 | 指标ID、当地观测日期/时间、观测值、适用的开高低收及成交量额、来源、发布时间（可得时）、首次及最近获取时间、质量状态 |
| 修订记录 | 观测身份、版本、旧值与新值、发现修订的时间、来源修订时间（可得时）、证据引用 |
| 采集运行 | 开始与结束时间、来源、请求范围、成功/失败、增量条数、错误原因、重试情况 |
| 最新快照 | 从有效历史观测生成的便捷视图；不作为唯一历史存储 |

## 写入、修订与缺失

- 同一序列、来源、观测日期/时间、口径的数据重复抓取时不重复插入。
- 同一观测的值发生变化时保留修订前后版本，不无痕覆盖。
- 日频与盘中数据使用不同频率或序列，不能用盘中抓取值覆盖已定义的收盘序列。
- 价格和金额采用可保留来源精度的数值表示，展示时才按需要四舍五入。
- 休市不生成新的交易观测；沿用旧值只用于界面展示并明确标记。
- 未发布、缺失、抓取失败与实际数值0分别保存和呈现。
- 原始证据按数据源使用条件保存，保留期限待定；解析后的历史观测建议长期留存。
- 历史数据库和原始文件不提交 Git；运行时需要独立备份和恢复验证。

## 回填建议

- 初次接入优先回填最近3年日频数据，具体深度取决于来源覆盖、权限和成本，尚未承诺全部可得。
- 对可低成本取得的官方利率序列，可保留更长历史。
- 记录每个指标的最早可用日期、缺口及回填状态。
- 日常增量采集同时复查近期数据，捕捉迟到发布与修订；复查窗口按来源设定。
- 更早的修订需要周期性核对或来源修订机制，不能假设近期复查可以发现所有修订。

## 比较规则

- 日变化对比上一个有效交易日或观测日，并明确标注基准。
- 周/月变化建议对比上周末/上月末最后一个有效观测值；跨期基准缺失时显示不可用。
- 价格涨跌幅使用同口径价格；基准为零时涨跌幅无定义，不返回无穷值。
- 利率和收益率变化用基点；期限利差须使用同一观测日期的数据，缺失时不拼接不同日期。
- 期货换月可能引入价格跳变，需标记换月，不能把换月价差直接解释为市场涨跌。
- 价格收益、复权价格收益与含分红总回报分开定义。
- 比较跨市场历史时明示各自交易日期；不默认前向填充代表真实交易价格。

## 未来实现的验收场景

1. 同一批数据重复采集，不产生重复历史行。
2. 某日接口失败后补采，历史曲线恢复且不产生虚假零值。
3. 来源修订某日数据，当前视图更新且旧版本可追溯。
4. 节假日不出现伪造的交易观测。
5. 指标的周/月变化能追溯到明确的基准观测。
6. 历史数据备份后能够恢复，并校验序列范围和观测数量。
